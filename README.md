# Ремонт уже установленных агентов

Пакет проверяет старую установку на Mac, Linux VPS и Windows. Hermes остаётся
на месте. Профили, проекты, переписки, память и авторизация сохраняются.

По умолчанию — диагностика и план. Изменения только при `repair --apply`:
инструменты Дизайнера, русский язык распознавания голосовых, старый помеченный
запрет фоновых задач, восстановление стандартного или пустого SOUL из проверенной
локальной копии пакета, очистка значений `secret=` в журналах. На VPS отключается
вторая служба gateway; на Mac сломанные медиапрограммы восстанавливаются по
закреплённым ссылкам и SHA-256. Личные настройки и дополнения сохраняются.

С выпуска TASK48 (FIX_0573) `repair --apply` также чинит на месте:
совместимость панели с Hermes 0.23 (импорт подтверждений в runner, preflight без
блокировки тем, метка Продажника), повторный `platforms:` в config.yaml перед
переходом на 0.23, проверку версии в старом `control/runner.ps1` Windows v2,
профильный AGENTS.md на Hermes 0.23, поставленном вручную, и дефекты Content
(тема `client`, PDF кадра, модель U2Net, временные файлы Mac) — в соседней
копии версии `<v>-repair1` (Linux) или `<v>-repair2` (Mac), исходный каталог
версии не меняется.

С FIX_0584 на Mac чинится вырезание человека (`person-cutout.sh`, BUG 0013):
в копию кладётся готовая проверенная программа `person-cutout` (универсальная
arm64 + x86_64, macOS 12+, SHA-256 закреплён, `vendor/bin/person-cutout`),
поэтому на Mac ученика ничего не компилируется; а в `Documents/Content/.venv`
ставятся Pillow, NumPy и OpenCV — CPython 3.12 через uv из установки Hermes и
колёса с закреплёнными хешами (`--require-hashes`, uv ищется так же, как его
ищет установка Content: PM Hermes 0.23, venv Hermes, `~/.hermes/bin`,
`~/.local/bin`, PATH). Программа, собранная на Mac ученика в `<v>`, в копию не
переносится — там всегда проверенная. Среда ставится только для скрипта,
который её читает (`skipped:script-not-repaired`, если копия не собрана). Без сети ремонт честно
отвечает `unavailable:network` и ничего не оставляет; на macOS старше 13
(Apple Silicon) или 14 (Intel) — `skipped:macos-too-old`. Копия прошлого патча
`<v>-repair1` заменяется новой `<v>-repair2`, сама не меняется.

Hermes 0.23.0, новые скиллы и агентов по текущему тарифу и бонусам доставляет
штатное обновление с новым кодом из кабинета; после него ремонт запускается ещё
раз (см. задание для Codex). Патч не получает тарифный пакет и не заменяет это
обновление. Windows v1/v2 требует Windows v3.

Запускайте из распакованной папки:

```sh
bash repair.sh diagnose
bash repair.sh repair
bash repair.sh repair --apply
bash repair.sh repair --apply
bash repair.sh verify --wait 60
```

Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File .\repair.ps1 diagnose`;
замените `diagnose` на `repair --apply` или `verify`. Параметр Bypass действует
только в этом процессе; системная политика не меняется. Скрипт сам не вызывает
изменение политики, UAC или новые окна. Если среда запрещает запуск, используйте
обычный PowerShell с разрешённым владельцем способом запуска.

На VPS выполняйте команды **на сервере по SSH**, от пользователя установки
(обычно root). Python берётся из Hermes; системный Python Windows не используется.

JSON сохраняется в `Downloads` с правами 0600 (на Windows права доступа наследуются
от личной папки пользователя; POSIX 0600 не является Windows ACL). Безопасные
результаты проверки состава отправляются существующим помощником диагностики
на платформу. `--no-report` отключает отправку, сохраняя локальный JSON.
Передаётся inventory установленного набора, а не произвольный JSON ремонта:
существующий API принимает только свой формат. Новый сервер не нужен.

`--home ПАПКА` задаёт домашнюю папку владельца; `--install-root ПАПКА` — папку
InfobizAgents; `--json ФАЙЛ` — место отчёта. `diagnose` и пробный `repair`
не записывают в установку, кроме описанного ниже повторного запуска панели; создание JSON в «Загрузки» — единственное исключение.
Второй ремонт не меняет установку и сообщает `changed:false`; каждый запуск
по-прежнему создаёт отдельный отчёт. Единственное исключение: при метке `web-shell-restart-pending`
`diagnose`, пробный `repair` и `verify` перезапускают только панель (Mac — bootstrap/kickstart,
Linux — `systemctl restart infobiz-web-shell.service`). Успех снимает маркер (`fixed`), отказ оставляет
его (`skipped:launchctl-unavailable`). Другие настройки эти команды не меняют.

Коды завершения: 0 — проверенные настройки исправны (либо составлен план);
3 — требуется штатное обновление / Windows v3; 2 — проверка или ремонт не выполнены;
1 — внутренняя ошибка. Пропущенная проверка панели не подтверждает её исправность.
Не объявляйте полный успех без разбора пропущенных проверок.
Неподтверждённые команды команды (`team-tools:<профиль>` со статусом
`pending:team-tools`) — предупреждение, а не код 2: настройки плагина применены,
а живая проверка через gateway повторяется командой `verify` после его запуска.
В `detail` такого предупреждения попадает короткий очищенный хвост вывода пробы.

На Mac `verify` проверяет локальную панель и без токена; ответ 401/403 в этом
случае отмечается как `skipped:panel-auth-required`. Личный SOUL без служебного
маркера допускает только отдельное предупреждение, если остальные проверки прошли.
Запрет Kanban без метки снимается только при false во всех купленных профилях;
при частичном выборе личная настройка сохраняется. На Linux ручной gateway
передаётся системной службе через штатный протокол Hermes с проверкой стабильности.
На Windows модели Content проверяются по SHA-256 блоками по 1 МБ, до 2 ГБ на файл.

Состав: `agents_repair.py`, два лаунчера, `known-baselines.json`, помощники в
`vendor/` (`designer-tools.py`, `student-runtime.py`, `security-tools.py`,
`student-skill-repairs.py`, `sync-tariff-panel.py`, `team-runtime.py` с `plugins/infobiz-team/`,
`agents-diagnose.mjs`, `profile-probe.py`, `panel-repairs.py`, `compat-repairs.py`,
`content-repairs.py`, `profile-context.py`), задание для Codex и изолированные тесты:
`npm run test:agents-repair-patch`. Сборка: `python3 -B installer/scripts/build-repair-patch.py
--version v2026.11.05.1 --output /tmp/agents-repair-release`.

Копии до изменений лежат в `control/tariffs/backups/repair-*/`; для конфигов
сохраняются только изменяемые несекретные настройки, поскольку полный конфиг
может содержать ключи. Полные `.env` и авторизация не читаются и не копируются.
Журналы сохраняются только после очистки. Автоматического отката нет: поддержка
сверяет резервную копию с текущими правками и восстанавливает нужные значения.
